# Contributing — Music Widget Oblivion

Thanks for contributing! This project follows a lightweight SDLC with practical quality gates.

## Workflow
1. Create a short-lived branch from `main`:
   - `feat/<short-name>`
   - `fix/<short-name>`
   - `docs/<short-name>`
   - `chore/<short-name>`
2. Commit using conventional commit prefixes.
3. Open a PR early; keep it focused.
4. Ensure checks pass and checklist is complete.

## Conventional Commits
Examples:
- `feat: add quick output switcher`
- `fix: handle missing Spotify playback state`
- `docs: update testing strategy`

## Pull Request Expectations
- Explain the change and motivation.
- Link issues/tasks when applicable.
- Add/update tests when behavior changes.
- Update docs for user-visible or architectural changes.

## Definition of Done
A change is done when:
- Acceptance criteria are met.
- Tests pass.
- Docs are updated.
- PR reviewed and merged.

## Code Style
- Prefer clarity over cleverness.
- Keep modules small and composable.
- Handle failure paths explicitly.

## Security & Privacy
- Do not commit credentials or tokens.
- Avoid logging sensitive user data.
